# PR8 explicit Run upgrade fixtures

`pr8-explicit-queued.sql` and `pr8-explicit-claimed.sql` were generated by the
unmodified PR8 `SqliteConversationStore` at merged commit
`6e7aa2ba4c27f6c4c375d5bc4bd4124decc20647`. They contain an actual single-member
explicit Group accept with `max_member_turns = 1`, first before claim, then
after `claimNextDispatch` but before execution start. They do not contain PR9
columns, indexes, or recovery tables. No columns were removed to fake an older
database.

The upgrade tests import these SQL snapshots before opening the PR9 store,
restore matching Group/Topic/Bot metadata, and use consumer activation to
recover and execute the first public handoff. Separate cases check nonterminal
states, larger/automatic/Direct budgets, migration rollback, and repeated open
without budget replenishment.

To regenerate, use an unmodified checkout at the exact commit above:

```sh
bun tests/unit/conversations/fixtures/generate-pr8-explicit-fixture.ts <pr8-checkout> tests/unit/conversations/fixtures
```

The generator checks the source commit and rejects changed PR8 source. It is
manual tooling; tests load committed fixtures without an old checkout.
