WP-4 touch targets (44x44, hit-tested at two phone widths)
==========================================================

Method
------
`expectTouchTarget` (e2e/fixtures.ts) asserts, per control:

  1. visible, then `scrollIntoViewIfNeeded()`;
  2. box stops moving (20 x 50ms poll) so a sheet/composer transform cannot be
     measured mid-flight;
  3. width >= 44 and height >= 44;
  4. the box lies fully inside the viewport;
  5. each of the four edge midpoints (2px in from the edge) resolves, via
     `document.elementFromPoint`, back to the control — the message on failure
     names whatever actually received the tap.

Records are appended to `touch-targets-wp4.jsonl` when `TOUCH_RECORD` is set;
every line carries the viewport and DPR it was measured at.

Correction (important)
----------------------
An earlier version of this helper wrote `elementFromPoint(x,y)?.closest(...) !== null`.
When the element was off-screen, `elementFromPoint` returned null, `null?.closest()`
was `undefined`, and `undefined !== null` is **true** — so a miss was recorded as a
hit, and the boxes in the first `touch-targets-wp4.jsonl` had negative y values.
That file and the "42 targets, 0 misses, 0 overlaps" line in commit 9ed5a7e8 are
wrong. This file, rewritten from the fixed helper, replaces them.

Three real defects the corrected test found, all fixed in the same pass
-----------------------------------------------------------------------
1. `transcript-speaker` used `[@media(pointer:coarse)]:-my-2` to keep its visual
   height while growing to 44. The negative margin pulled it under the previous
   row, so its top midpoint went to the neighbour. Removed: the speaker line is
   now 24px taller on coarse pointers — a real layout change, recorded here.
2. The group bar's member-panel disc was 36x36 (h-9 w-9). Now 44x44 on coarse
   pointers; the 28px collage inside is unchanged, and the capsule grows from 36
   to 44 inside the 52px bar.
3. The group bar's topic pill laid out 127px inside a 117px flex track, so its
   right edge sat 4px *under* the ⋯ disc (painted later, so it won the taps). The
   slot now caps the trigger (`[&_button]:max-w-full`) and clips
   (`overflow-hidden`); the 390 test asserts `pill.width <= slot.width` and that
   no two bar controls' boxes intersect.

Layout/visual changes, stated plainly
-------------------------------------
Desktop (fine pointer) density is untouched: every enlargement is behind
`@media (pointer: coarse)`. On coarse pointers the speaker line grows by 24px,
the instance segments grow from 24 to 44 tall, and the copy button occupies 44
instead of 22.

Not measured
------------
- Real devices (all numbers are Chromium emulation: Pixel 7 and a 390x844
  viewport with `hasTouch`).
- WebKit/Safari: this repo has no webkit Playwright project.
