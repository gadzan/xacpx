# Runtime Permission

`src/bridge/engine/runtime/runtime-permission-policy.ts` + `runtime-permission-resolver.ts` — xacpx-owned parser/resolver and live snapshot for the acpx Runtime.

- **Parser:** `XacpxPermissionPolicy` (`autoApprove`, `autoDeny`, `escalate: string[]`, `defaultAction: approve|deny|escalate`); JSON object only, `string[]` must be non-empty, unknown field → fail-closed, empty/unreadable file or inline invalid JSON → `RUNTIME_INIT_FAILED` (never fallback to `approve-all`). `isEligibleForRuntime` gates `nonInteractivePermissions=fail` and `escalate` → Runtime ineligible.
- **Resolver:** precedence `autoDeny → autoApprove → escalate → defaultAction → permissionMode` (`approve-all`/`deny-all`/`approve-reads` where only `inferredKind=read|search` approves, else `nonInteractivePermissions`). Exact token matching against `permissionMatchTokens` (normalized lower-case tokens from `kind`, `rawKind`, `title`, `toolName`, `title head`); only rule `"*"` is wildcard, no `globToRegExp` (`*` suffix, `?`, `**` are literal).
- **Snapshot:** `RuntimePermissionConfig` (`generation`, `permissionMode`, `nonInteractivePermissions`, `permissionPolicy`) ; single source `configFromRaw` (no drift). Worker holds `permissionSnapshot`/`permissionGeneration`, `onPermissionRequest` reads snapshot.
- **Live update:** `EngineRouter` prepare (preflight `busy`/`acquiring` fail-closed) → `commit` validates, `generation++`, fans out `permission.update` (explicit `clearPermissionPolicy` for clear) to all live workers while holding transition lock; `ACK` kept, `fail` workers terminated (`lock` held) or `RUNTIME_WORKER_TEARDOWN_PENDING` if teardown also fails; new workers bootstrap with current generation via `ensure` `permissionGeneration`.
- **Channel interaction:** `needs_interaction` requests carry an opaque `interactionId` bound at prompt dispatch (`src/commands/handlers/session-handler.ts` → `PermissionInteractionBroker.bindTurn`) to the exact originating turn (chatKey/account/initiator/origin). The worker fails closed without one, so scheduled/peer/orchestration turns stay non-interactive. Daemon `resolvePermissionRequest` delegates to the broker (`src/permissions/`), which routes by `interactionId` — never by session-level latest-chat state — to `MessageChannelRuntime.requestPermission()` (Discord buttons first; 120s business deadline, 125s transport watchdog). Initiator-only approval, first-terminal-decision-wins, memory-only pending state, every error path → `reject_once`. Full plan: `docs/superpowers/plans/2026-09-12-channel-permission-interaction-plan.md`.
