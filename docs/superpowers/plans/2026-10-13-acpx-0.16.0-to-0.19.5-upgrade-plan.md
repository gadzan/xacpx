## 0. 目标、约束及证据等级

### 0.1 目标

1. 在 **CLI Engine** 和 **Runtime Engine** 中验证 acpx 0.19.5 兼容性，在不丢历史、不重复执行 prompt、不误杀进程的前提下升级。
2. 处理 xacpx 对 acpx **内部持久化与 Queue Owner 锁布局**的耦合；尤其是旧 `index.json` 依赖和按 PID 回收。
3. 在升级稳定后，按收益选择性复用 0.17–0.19 的公开能力：模型检查、会话权限、`fs/terminal`、观测/游标回放和共享会话控制。
4. 明确 release gate、差异测试、灰度/回滚和 PR 拆分，避免把依赖更新与 Runtime 架构替换混为一个改动。

### 0.2 硬性约束（延续现有架构决策）

- **不改/fork/patch/vendor acpx**，不引入上游私有 `src/*`/`dist/*` imports；只使用已发布的 `acpx/runtime` 等**经仓库准入审查**的公共入口。若增用 `acpx/agent-registry` 等入口，先显式调整 `scripts/lint-acpx-imports.mjs` 的 allowlist 并有测试，不能绕过规则。
- 保留 `SessionService` 的逻辑会话/alias/绑定与 **session 级 Engine affinity**；同一物理会话不能按方法随意跨 CLI、Runtime Engine 路由。
- Runtime 继续保持每会话独立 Worker、fence、generation、host crash-safety 和权限 broker；上游的 ACP agent root 生命周期改进**不能替代** xacpx 对 Worker 以及后代进程的所有权证明。
- 保留 CLI / Bridge / Runtime 三条实际运行链路；默认引擎或用户配置不在基础升级阶段改变。
- 不直接公开上游对象、内部路径或不受验证的 agent 身份给 Channel/Relay/Web；继续经 xacpx-owned `runtime-contract.ts` 和 transport/Control DTO。
- 把 `~/.acpx` 看作上游持久化域，`~/.xacpx` 看作本项目状态域。禁止未经 identity/owner 验证的跨域重写和强制回收。
- 本计划中没有一项“测试通过”声明：**截至本 PR，仅完成 GitHub 源码/发布记录静态核查，没有实际安装目标版本或运行 CI。**

### 0.3 证据状态

## 1. 基线与版本差异

### 1.1 当前 xacpx 的依赖和实际解析

- 根 `package.json` 直接固定 `acpx: 0.16.0`；`bun.lock` 也需要随升级更新，**不使用 `^0.19.5`**。
- xacpx 和 acpx 0.19.5 的 `engines.node` 均为 `>=22.13.0`，暂无由最低 Node 引擎版本产生的直接阻断。
- `src/config/resolve-acpx-command.ts` 对 CLI 命令的优先级为：`transport.command` 明确覆盖 → bundled package → `PATH`。因此 **仅升级 npm 依赖不保证外部命令是 0.19.5**。Release gate 需记录实际生效的绝对命令路径、来源与 `acpx --version` 结果。
- 构建以 Bun 为主，根 `build` 对 `acpx` 标记 external；CLI 子进程和 Runtime 的有效运行路径需要分别检查，而不能只靠 `tsc` 推断。
- 正式受控导入点是 `src/bridge/engine/runtime/runtime-adapter.ts`；既有例外包含 `src/transport/agent-registry.ts` 的 lazy `require("acpx/runtime")`。已有 `scripts/lint-acpx-imports.mjs` 必须继续生效。

### 2.1 已确认的两条内部耦合

**A. 旧 index 不再是权威发现来源。** 上游 0.19.5 `src/session/persistence/discovery.ts` 实现 `scanSessionRecords()`：扫描 `sessions/*.json`、跳过 `index.json`、按有效 record 身份校验后返回。上游 [sessions 文档](https://github.com/openclaw/acpx/blob/v0.19.5/docs/sessions.md) 明确写明 legacy `index.json` 被忽略。xacpx 的两个读取模块还以这个文件为起点，**存在确定的设计不一致**；只有跑过新建/迁移 fixture 后才能确定哪些实际场景已经失败。

**B. 手写终止路径不等于上游所有权协议。** xacpx `terminateAcpxQueueOwnerWithDeps()` 的 POSIX 路径读取锁内 PID、调用 `terminateProcessTree()` 后 unlink；`readQueueOwnerPid()`/`defaultOwnerAliveCheck()` 则将 PID 存活当作 owner 存活线索。上游 0.19.0+ 引入进程出生身份、generation、retirement receipt 等更强证据。**仅凭 PID 与文件存在不能批准终止**。Windows 路径当前拒绝无法证明身份的锁，不能为了升级方便放宽这个 fail-closed 行为。

### 2.2 需要验证而非预设修复的点

- xacpx 不直接解析 `.stream.ndjson` ACP 消息时，0.17 的本地 marker 并不必然影响当前业务；逐一检查所有日志读取、`.stream.*` 删除、回滚和历史复原路径，而不是盲目重写所有解析器。
- 上游仍支持 `--json-strict`、`--ttl`、`--no-wait`、`--filter-cwd`、`--agent` 等 CLI 形状；不能无证据将命令构造器判定为破坏性 API 变化。
- `AcpRuntime` 0.16 已有 `setModel`/`getCapabilities`/`shutdown`；不能把已有功能当作此次新增。
- `sessionPermissions` 是**建连/重连时的权限解析**，并不能替代 xacpx 的 live permission-generation 更新与在途 request fence。
- `fs:false`、`terminal:false` 是 ACP callback capability policy，不限制 agent 自己可执行的 OS 文件系统/终端操作；不作为沙箱或安全认证依据。

### PR-B：重构内部会话发现/历史兼容（阻断发布）

**改动文件：**
- `src/transport/native-session-history.ts`
- `src/transport/acpx-session-index.ts`
- 必要时新增 `src/transport/acpx-record-discovery.ts`（**xacpx-owned** 受控读取适配器，而非私有 acpx import）。
- `src/bridge/engine/runtime-engine.ts` 中同类扫描/匹配逻辑应复用经测试的纯 predicate，保留删除场景的更严 fail-closed 原则。
- `tests/unit/transport/native-session-history.test.ts`、`acpx-session-index.test.ts`、`tests/unit/bridge/engine/runtime/runtime-record-compat.test.ts`、`tests/compat/acpx-latest.test.ts`。

**实施细节：**

1. 先确定是否有已发布 API 可以满足目标查询：`sessions show/history` 由 `(agent,cwd,name)` 寻址；`readNativeSessionHistory` 当前是按 **provider 的 `agentSessionId`** 找过去记录，不能假设 CLI 能按这个 ID 查询。无法满足时允许隔离的 record scanner。
2. scanner 只扫描已知 `sessionsDir` 下普通 `.json` 文件，跳过 `index.json` 和 xacpx Tombstone；避免跟随符号链接/特殊文件；采用容量、文件大小及并发读限制，防止用户态目录导致无界 I/O。
3. 逐记录先做非破坏性的形状校验和 path↔ID 校验（上游采用 `encodeURIComponent(acpxRecordId) + ".json"`）；匹配身份时至少考虑 `acpxRecordId`、`agent_command`、`cwd`、`acp_session_id` 及可用的名称/关闭状态。不得把“同名”推成“同一物理 session”。
4. native history 保留现有 `mapAcpxMessagesToHistory()` 的 text/reasoning/tool 顺序、`Resume` 跳过、重复 provider ID 时的确定性选择；历史缺失允许 best-effort `[]`，但要有**可观测诊断**，不能悄悄把真实 I/O 权限错误当成“没有历史”。
5. `resolveSessionAgentCommandFromIndex` 需改为从最新 canonical record 获取；对多候选/身份不一致返回明确 ambiguous/unknown 或维持严格不匹配，禁止随机选择第一个。
6. 区分 **读取**和 **删除**：读取失败可降级并保留用户会话；删除/写入出现不确定身份必须 fail closed。
7. 用 0.16 legacy、0.19 current、混合 record fixture 验证 scanner；对 index 缺失、过期索引、记录损坏、文件移除竞态、重复 provider ID、并发 checkpoint 做测试。

**验收场景（必须可自动运行）：**

| 输入 | 期望 |
| --- | --- |
| 0.19.5 新 record，没有 `index.json` | 能发现并恢复对应历史 |
| 有 index 但记录内容/地址已更新 | 以验证过的 record 为准 |
| 同一 provider ID 对应多个本地 record | 只按受支持的选择规则取历史，禁止跨 agent/cwd 泄漏 |
| 文件名/`acpx_record_id` 不一致 | 不采信，记录诊断 |
| 不可读取目录/文件 | attach 不被误报成成功找到了历史；删除链路拒绝 |
| record 正在原子替换或被关闭 | 受控重试或明确未找到，不返回不完整捏造结果 |

**禁止捷径：** 不直接 import `acpx/src/session/persistence`；不把 legacy index 继续做唯一真相；不直接把上游扫描器复制成永远不变的协议承诺。

### PR-C：Owner / Lock / Record / Journal 删除安全（阻断发布）

**改动文件：**
- `src/transport/acpx-queue-owner-launcher.ts`
- `src/transport/queue-owner-reaper.ts`
- `src/transport/acpx-session-argv-migration.ts`
- `src/transport/acpx-session-files.ts`
- `src/bridge/engine/runtime-engine.ts`（删除 Tombstone 和 physical identity）
- ``src/bridge/engine/runtime/runtime-worker-manager.ts` / `runtime-worker-fence.ts`` 仅在回归证明必须时修改
- 相关 `tests/unit/transport/*queue-owner*.test.ts`、`acpx-session-files.test.ts`、`acpx-session-argv-migration.test.ts`、`tests/unit/bridge/engine/runtime/runtime-engine-delete.test.ts`、`runtime-close-parity.test.ts` 等。

**协议级要求：**

1. 先记录新旧版本锁文件的真实格式和作用域（`record ID → lock path`）、PID、Owner generation、birth identity 和参与者版本。任何缺失、畸形、过期证据不允许转为强杀授权。
2. **区分操作的业务语义：**
   - `cool/freeWarmProcess`：释放物理 Owner、保留逻辑会话与可恢复 history；
   - `cancel`：只取消允许的当前 Turn，不等于 close/delete；
   - `close`：按引擎契约软关闭；
   - `hard-delete`：先拒绝新请求、完成 fence/取消与所有权确认，再删除**精确目标**数据；
   - `shutdown`：等待已接纳工作并完成受控退出，不把 unknown 当 success。
3. **首选公开/受支持的 Owner 生命周期操作**；如果不能非破坏性地停止目标 Owner，不允许以 `sessions close` 伪装 cool。可以保留自有外部进程管理，但前提是证明 identity（不仅是 PID）和原锁仍属于预期 owner，且无 TOCTOU 窗口。
4. 对无法充分证明的 Windows/POSIX 目标一律 fail closed，保留恢复/手工诊断路径；不能在读取 PID 后先杀再补验证，也不能删除可能属于继任 Owner 的 lock/socket。
5. 继续遵守 xacpx physical identity / sibling alias 聚合；共享一物理 session 的不同逻辑别名不能互相终止在途 Owner。混合版 Owner 若缺新版能力，允许自然 TTL 退出或可验证的显式收尾，不推定强制回收安全。
6. `acpx-session-argv-migration` 的写入采用读前/读后身份确认、精确目标锁验证，并保持幂等。若上游已能恢复 legacy builtin 命令，先用测试证明后再缩减迁移，不直接删现有逻辑。
7. **删除的两阶段界面：** xacpx Tombstone/删除屏障 → 确认 target、父/子进程和 record owner 无活跃写入 → delete record/event files → 校验结果 → 完成 Tombstone。任何阶段故障留下可恢复、可重试状态，而不是“假成功”。
8. 优先考察上游 `sessions prune --include-history` 的职责；其语义是清理符合条件的 **closed records**，不能天然替代 xacpx “按特定 record ID 真实删除”。如果无法满足精确目标和时序要求，保留独立删除适配器并有新版本差异测试。
9. `.stream.ndjson` 已有 local lifecycle markers，禁止把它们冒充 ACP JSON-RPC；文件 segment 轮转/锁/占用失败按上游规则处理。历史导入/保留策略可验证，不直接删除仍被 watcher 读取的无授权文件。

**必须覆盖的故障注入：**
- 读锁后 PID 重用；新 Owner 抢占同一路径；旧清理延迟抵达；
- Owner 在 terminate 前退出、terminate 后仍占用记录、读锁/读 record 权限不足；
- 并发 `ensure/import/close/prune/delete`，session record checkpoint 正在提交；
- Worker crash / daemon restart / CLI 与 Runtime sibling alias 混跑；
- POSIX process group 脱离与 Windows root 已退出但子进程仍活跃；
- journal 已轮转、关闭后 watcher 正在 drain、Windows EBUSY/EPERM。

**验收：** 对身份不确定的进程 **零强杀、零解锁**；对删除失败明确返回 pending/failure，目标之外的会话/历史/进程无变动。**如果无法安全完成本 PR，升级 PR 不进入发布。**

### PR-D：使用公开 Runtime 控制、权限和模型能力（建议升级后推进）

**改动文件：**
- `src/bridge/engine/runtime/runtime-adapter.ts` / `runtime-contract.ts`
- `src/bridge/engine/runtime/runtime-worker-main.ts` / `runtime-worker-protocol.ts`
- `src/bridge/engine/runtime/runtime-permission-resolver.ts` / `runtime-permission-policy.ts`（必要时）
- `src/transport/agent-registry.ts`、`src/agents/` / 能力查询服务、诊断与产品 DTO（按真正调用链落地）

**设计：**

- `startTurn` 和 `setMode/setModel/setConfigOption` 支持传入有严格来源的 `AbortSignal` 与同步 `assertActive`，在准备、排队或取得 owner 后、**写入前**重查 xacpx cancellation/generation/authorization；控制已发送并被接受后必须等待回执和 checkpoint，不能撤销已生效状态。
- **权限不变式：** Runtime 构造时的 `sessionPermissions` 只对新建/重连客户端生效；x acpx 的现有 live policy generation、broker pending request cancellation、Worker poison/fence 仍是权威。任何新能力必须由实际频道/UI/host 可处理的权限能力驱动，不能谎称会处理 interactive forms。

- 将 `getCapabilities/getStatus` 标准化到 xacpx DTO：当前模型、原生显示名、可选 models、配置项、usage、可用控制；未知/null 与 0 严格区分。`setConfigOption` 继续使用上游返回的 accepted snapshot，不能保存“未经 agent 确认”的值。
- 试点 `inspectAgentModels({ agentCommand: string[], cwd, signal?, timeoutMs?, agentProcessEnv? })`：从已解析/允许的实际 agent 命令产生，不在 Web 接受任意 argv；隔离工作区与 child-only 环境；超时、取消和失败回收；区分 `unsupported`、`needs-setup`、`timeout` 和有效空模型。
- **模型探测副作用：** 官方接口不要求 xacpx 的 sessionStore，但可能创建 agent-native session history；结果缓存绑定 agent command/argv、workspace、认证/环境配置修订以及 adapter pin，防止跨用户/跨目录复用。
- `runtime-worker-main.ts` 的单 Worker/单 Runtime、immutable ensure identity、`promptStarted` 注册先于等待、最终结果分离都保留。底层修复更强不等于可以删掉 host fence。

**验收：** 用户取消在写前阻断；晚到 permission 不会授权后继 Turn；model/effort 的 accepted 结果和 reconnect 后一致；无广告时不虚构候选；模型探测不会泄露命令/token 或影响现有正式会话。

### PR-E：Shared Runtime / Watch 可行性验证（P2，不阻断基础发布）

**使用条件与非目标：**

- 上游 [shared sessions](https://github.com/openclaw/acpx/blob/v0.19.5/docs/shared-sessions.md) 明确：`createSharedAcpRuntime()` 面向当前 CLI Queue Owner，支持 persistent prompt；**不支持**自定义 `sessionStore`、`agentProcessEnv`、`mcpServers`、`sessionPermissions`、`processLifecycle`、每 Turn permission/elicitation、`mode: "steer"` 等本项目重要能力。
- Shared Runtime handle 与 in-process Runtime handle **不是可互换**的 owner 契约；不要混传；不把整个 `RuntimeEngine` 改造成 Shared Runtime。
- 共享控制依赖已经运行的 Owner；无 Owner 时可能返回 `ACP_BACKEND_UNAVAILABLE`。不能自行“起个直接连接”去改变同一会话，防止双 Owner/新 provider session。
- `watchSession` 是只读观察者，不等于任务接管，不拥有取消权限。`cursor` 不透明、按本地 record 作用域排序，断开重连后独占位置续读；不能解码比较或对不同物理 session 混用。
- `turn.promptStarted` 是实际 ACP transport 接受后才完成，`turn_result` 是 Turn 结算结果；提交连接断开后的 `WATCH_OUTCOME_UNKNOWN` 必须呈现为未知，**绝不能自动再次提交同一 prompt**。`requestId` 仅关联而非幂等键。

**POC 任务：**

- [ ] 仅为 **CLI Engine** 选择一条可隔离的试点路径（例如被动 watch），不重写 Runtime Engine/SessionService。
- [ ] 用现有 Queue Owner 通过 `createSharedAcpRuntime` 建 observer；断开后按 cursor 恢复，检查 replay 与实时事件不重复、不乱序。
- [ ] `message`/`turn_started`/`turn_result` 转换为 xacpx-owned DTO，关联真实 requestId/physical session，保留空/unknown outcome。
- [ ] 旧 Owner 返回 `WATCH_OWNER_UNSUPPORTED` 或 `QUEUE_SHARED_RUNTIME_UNSUPPORTED` 时降级为既有观察方式，不能伪造观察结果或强制关闭他人会话。
- [ ] 验证共同 OS 用户/home/cwd/agent command identity；跨 cwd、不同 adapter、同名 alias 不能互相观察。
- [ ] 试用 setMode/setModel/setConfigOption/getCapabilities 但与当前 CLI 控制流程做 differential；决定哪些局部 CLI shell-out 真正值得删除。
- [ ] 如需推广 Relay/Web，多客户端观察者不得改变 Turn 执行所有权、不能将 replay 当作新消息导致重复通知。

**POC 终止条件：** 不能证明无重复下发/权限隔离/owner identity 时，只保留实验性代码，不开启功能或删除原实现。

### 4.3 明确的结果判定

- **不重复执行**：连接丢失、超时、取消后禁止对 outcome 不明的 prompt 自动 retry；必须等待 watch/history 或向用户报告 unknown。
- **不丢历史**：已持久化的文本、思考、tool、使用量和断线后接受的配置仍然可查询；没有日志不等于把历史重置为空。
- **不误杀**：进程身份不明时 0 次主动终止/删锁；继任 Owner、无关进程和兄弟 alias 不受影响。
- **不越权**：已撤销 permission / generation 的请求在写入之前被挡住；晚到结果不能修改新代状态。
- **不混账本**：相同 provider session ID、不同 acpx record ID 或不同 cwd/agent 不互相继承历史、锁和模型。
- **不假成功**：物理删除/关闭未验证、journal 占用、shutdown 超时必须显示 pending/failure，并留下可修复状态。
- **可回滚**：保留旧运行环境、真实命令版本记录和隔离复制的旧数据；降级前不得默认假设 0.16 能完全理解 0.19 已更新的状态。

### 5.1 Release gate（全部满足才允许合并发布升级）

- [ ] Linux + Windows 必需回归通过；macOS 可用则补充；失败项有明确不发布理由。

- [ ] 更新 changelog/运维文档，包含最低 Node、有效 acpx 检查步骤、老 Owner 迁移、回滚注意事项。

### 5.2 灰度/更新顺序

1. 备份有业务数据的 `~/.acpx`、`~/.xacpx`（加密/限制权限，不提交至仓库）；保存目标系统与 acpx CLI/runtime 的实际版本信息。
2. 在隔离 HOME 用 **0.16.0 数据副本**执行 0.19.5 升级，检查历史/记录/锁；禁止试验代码触碰用户真正状态。
3. 停止接纳新 Turn；等待当前 Turn settle，再停止 daemon/Bridge/Worker；对于 CLI Queue Owner 应让旧版本 Owner 按既有 TTL 自然退出或用经过验证的非破坏性释放方式处理，不强杀未知 PID。
4. 安装和启用 0.19.5 的 **所有参与客户端**；避免旧 CLI Owner 与新版共享控制长期混跑。必要时先保留 CLI 旧路径，单独完成 owner 过渡。
5. 小范围启用，先查会话列表/历史（只读），再执行创建/提示/控制/取消，最后演练删除。监控 orphan/fence、未知 outcome、record 读失败和重复通知。
6. 放量前复核外部 `transport.command`：如果指向旧版本，应显式阻断共享能力或提供操作提示；绝不将“bundled 0.19.5”冒充“所有进程均为 0.19.5”。

### 5.3 回滚

- 先停用升级实例、阻断新请求，记录未结算/未知结果，避免在 rollback 时再次执行。
- 恢复升级前保存的完整 `~/.acpx` / `~/.xacpx` 状态和对应 acpx/xacpx 程序版本（若已执行新 Turn，先由操作者决定保留/导出新增工作成果，不能无提示覆盖）。
- **不可假设** 0.19 写过的 record/journal/owner lease 能被 0.16 完全读取，更不能先降级后让旧版清理新版锁。
- 回滚后只用隔离测试确认旧状态/记录/访问权限，验证没有残留新 Owner 与被误删历史；失败保持停止状态并提供诊断，而不是自动二次重试。

## 6. 明确暂不做

- 不以 `createSharedAcpRuntime` 代替当前 per-session Runtime Worker；Shared Runtime 明确不覆盖自定义 store、环境、MCP、过程钩子、interactive approval 和 steer 等本项目要件。
- 不把 0.19 的 ACP `fs/terminal` 能力开关宣传为 OS sandbox。
- 不顺手改默认引擎、CLI 输出 UI、Bot/Group 产品语义、Discord/Feishu 插件、adapter 具体版本。
- 不重构整个 SessionService/Bridge protocol/Worker Fence；只在直接受影响且被测试覆盖的地方改。
- 不引入 runtime 私有 imports 来“方便扫描会话或杀 Owner”。
- 不把 `requestId` 当作可安全自动重试的幂等键，不把 `watchSession` 当作任务接管 API。
- 不清理旧版支持/兼容 fixture，直到迁移、降级矩阵得到明确证据。
