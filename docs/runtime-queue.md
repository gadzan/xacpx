# Runtime Durable Queue

`src/bridge/engine/runtime/runtime-queue.ts` — xacpx-owned durable FIFO for Runtime-bound sessions.

- **Location:** `~/.xacpx/runtime/runtime-queue/<logicalSessionId>.json` (via `coreHomeDir(homedir())/runtime`), not `~/.acpx`.
- **Schema:** `xacpx.runtime-queue.v2` with `logicalSessionId` and `items: RuntimePendingMessage[]` (`messageId`, `text`, `acceptedAt`, `mode: queue|auto`, optional `mcpCoordinatorSession`/`mcpSourceHandle` per head + `mcpIdentityKnown` discriminator). `v1` is legacy (no per-head discriminator) — readable, but any head with `mcpIdentityKnown !== true` (legacy `v1` or pre-discriminator `v2` mixed record after bump) fails closed on drain (`RUNTIME_INIT_FAILED`, keep head; operator clear required — no automatic migration, clearing will also drop subsequent known heads as FIFO cannot skip); new `v2` writes set `mcpIdentityKnown:true` (absence = intentional none).
- **Atomicity:** `write tmp → rename → readback validate` (`suspended` included in verify: `items.length` + `!!suspended`); corrupt/unreadable → `RUNTIME_INIT_FAILED` fail-closed, never empty.
- **Idempotency:** same `messageId`+same `text` → idempotent queued receipt; same `messageId`+different `text` → `RUNTIME_QUEUE_CONFLICT` fail-closed.
- **Limit:** `RUNTIME_QUEUE_MAX_DEPTH=20` → `RUNTIME_QUEUE_OVERFLOW`.
- **Ack:** only after durable persist; `store.enqueue` holds per-key `withLock` that also gates `deleting`/`coolPending` so delete and enqueue share an atomic boundary.
- **Drain:** `RuntimeEngine.drainLoop` is single-flight per `logicalSessionId` (`draining` map), reuses `executeRuntimeTurn` (same lifecycle as direct prompt), dequeues only on terminal `completed`/`failed`/`cancelled`/`permission_denied` (crash keeps head for at-least-once replay and re-kicks after backoff, respects `shuttingDown`). On daemon startup, `AcpxBridgeTransport.primeRuntimeQueues` sends authoritative runtime-bound sessions from the session catalog to the bridge host via the `primeRuntimeQueues` bridge RPC, calling `primeQueuesFromCatalog` on `RuntimeEngine` to enumerate queue journals and immediately resume draining without waiting for manual session interaction.
- **Concurrency:** per-`logicalSessionId` `turnLease` (`turnLeases` map) serialises direct `prompt` vs `drainLoop` (maxConcurrent=1). `activeTurns` is a refcount `Map` (inc/dec) so `preparePolicyTransition` (plan §32) sees busy during lease wait; `acquireTurnLease` checks `shuttingDown` and releases on throw. `drainLoop` and `prompt` share the same lease.
- **Archive suspend:** `queueSuspended` (`Set` + durable `suspended` flag in `runtime-queue/<id>.json`) is set by `freeWarmProcess` (archive) when a durable queue has pending items — `freeWarmProcess` persists `suspended=true` **before** adding to memory (fail-closed: on persist failure it throws `RUNTIME_INIT_FAILED` and does not cool), `prompt` persists `suspended=false` before deleting from memory (on failure it `decActiveTurn` and throws). `kickDrain`/`drainLoop` (entry, `while` head, and before `dequeueHead`) return immediately while suspended, keeping the head only for non-terminal (crash) replay; terminal `completed` heads are dequeued even when suspended — suspend only blocks the next head admission (the previous `keep-head` for terminal has been corrected). The suspend path also consumes `coolPending` (terminate + release) so the worker does not stay warm after archive; a direct `prompt` clears the suspend and re-kicks drain. `deleteSession` clears suspend in both inner and outer `finally`.
See `src/bridge/engine/runtime-engine.ts` for TTL/delete/cancel integration and `tests/unit/bridge/engine/runtime/runtime-queue.test.ts` for gates.
